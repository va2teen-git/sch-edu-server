# Стратегия тестирования (Testing Guide)

Проект использует комбинированный подход к тестированию, учитывая монолитную архитектуру (Flask + Vanilla JS + Jinja2) и строгие требования к надежности платформы (особенно во время школьных занятий).

## Архитектура тестов

Основываясь на лучших практиках тестирования веб-приложений (Test Pyramid), наша архитектура разбита на следующие уровни:

1. **Unit-тесты бэкенда (Backend Unit Tests):**
   - **Инструменты:** `pytest`, `pytest-flask`.
   - **Цель:** Проверка бизнес-логики в `app.py`. Проверяется обработка авторизации (`/login`), логика дашборда учителя (`/teacher`), сбор телеметрии (`/telemetry`) и алгоритмические проверки ответов (например, функции проверки четности, Хэмминга).
   - **Изоляция:** Используется **in-memory SQLite база данных** (`sqlite:///:memory:`). Тесты не затрагивают основную базу `school_data.db` и не оставляют мусора.

2. **Интеграционные тесты / E2E (End-to-End) тесты:**
   - **Инструменты:** `Playwright` (для Python).
   - **Цель:** Симуляция действий реального ученика в браузере.
   - **Что проверяют:**
     - Работу кнопок "НАЧАТЬ ЗАДАНИЕ" (скрытие интро, показ рабочей области).
     - Работоспособность "Глобального Хардкор-режима" (сохранение в `localStorage`, перезагрузка страницы при ошибке).
     - Отправку телеметрии из браузера на бэкенд в реальном времени.

## Структура папки `tests/`
```text
tests/
├── conftest.py       # Фикстуры pytest (создание тестового приложения, in-memory БД)
├── test_backend.py   # Unit-тесты для маршрутов и логики Flask
└── test_e2e.py       # (Резерв) E2E тесты с использованием Playwright
```

## Как запускать тесты

Все тесты запускаются с помощью команды `pytest` из корня проекта.
Вам потребуется установленное виртуальное окружение с зависимостями:
```powershell
# Активация окружения (если не активировано)
D:\py-env\venv\Scripts\Activate.ps1

# Запуск всех тестов
pytest

# Запуск тестов с подробным выводом (-v)
pytest -v

# Запуск конкретного тестового файла
pytest tests/test_backend.py
```

## Как писать новые Unit-тесты

Если вы добавляете новый урок или функцию проверки (например, `/check_new_math`), обязательно напишите для нее тест в `test_backend.py`.

**Пример (Шаблон теста):**
```python
def test_new_math_endpoint(client):
    # 1. Arrange: Подготовка данных
    payload = {"answer": "42"}
    
    # 2. Act: Выполнение запроса к тестовому клиенту
    response = client.post('/check_new_math', json=payload)
    
    # 3. Assert: Проверка результата
    assert response.status_code == 200
    data = response.get_json()
    assert data['success'] is True
```

**Особенности работы с сессией:**
Чтобы протестировать роуты, требующие авторизации (например, `/teacher`), используйте фикстуру и метод `session_transaction()`:
```python
def test_teacher_dashboard_access(client):
    with client.session_transaction() as sess:
        sess['student_name'] = '#учитель#'
        sess['grade'] = 'teacher'
    
    response = client.get('/teacher')
    assert response.status_code == 200 # Успешный доступ
```

## Требования к ИИ при написании тестов
При генерации новых тестов нейросетью:
1. Обязательно использовать фикстуры `client` и `app` из `conftest.py`.
2. Покрывать как успешные сценарии (Happy Path), так и негативные (неверные ответы, отсутствие данных в POST-запросе).
3. Следить за тем, чтобы тесты телеметрии проверяли корректный формат JSON (согласно стандарту в `LESSON_REQUIREMENTS.md`).


## Описание текущих реализованных тестов

На данный момент в проекте реализованы следующие автоматизированные тесты, которые покрывают критический функционал сервера и клиентской логики.

### 1. Бэкенд тесты (`tests/test_backend.py`)
Проверяют внутреннюю бизнес-логику Flask-сервера и работу с базой данных:

*   `test_login_student`: Проверяет успешную авторизацию стандартного ученика, запись сессии и редирект в меню уроков.
*   `test_login_teacher`: Проверяет успешную авторизацию учителя (по кодовому имени `#учитель#`) и перенаправление на страницу дашборда.
*   `test_teacher_route_unauthorized`: **Проверка безопасности.** Гарантирует, что обычный ученик при попытке прямого перехода на `/teacher` не получит доступ к панели учителя.
*   `test_telemetry_post`: Имитирует получение стандартизированного JSON-пакета с телеметрией от урока, проверяет его валидацию сервером и корректное сохранение в таблицы `TaskAttempt` базы данных.
*   `test_check_parity`: Проверяет конкретный алгоритмический эндпоинт (`/check_parity`) на предмет правильности ответов для модуля "Помехоустойчивые коды (Четность)".

### 2. Сквозные тесты (E2E) браузера (`tests/test_e2e.py`)
Используют `Playwright` для эмуляции реального пользователя в headless-браузере Chromium. Для обхода ограничений многопоточности Windows эти тесты автоматически запускают Flask в параллельном фоновом потоке с использованием `Werkzeug make_server`.

*   `test_login_and_navigate`: 
    - Открывает страницу логина, вводит имя "E2E Student" и корректно выбирает класс из тега `<select>`.
    - Переходит в меню и кликает по карточке урока "Законодательство в области ПО".
    - **Тест UI-стандарта:** Проверяет, что рабочая область (workspace) скрыта, а блок-интро виден.
    - Кликает кнопку "НАЧАТЬ ЗАДАНИЕ" и проверяет, что интро исчезло, а рабочая область корректно отобразилась.
*   `test_teacher_dashboard_sees_student`: 
    - Авторизуется как учитель в дашборде.
    - Проверяет, что сгенерированная в предыдущем тесте нулевая телеметрия (при нажатии "Начать") успешно долетела до сервера и ученик "E2E Student" появился на экране дашборда.
