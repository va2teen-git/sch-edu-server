# School Educational Server (sch-edu-server)

## О проекте
`sch-edu-server` — это кроссплатформенный образовательный веб-сервер для проведения интерактивных уроков информатики. Платформа разработана специально для нужд школ и предоставляет уроки с теорией, встроенную проверку кода (autograding) и панель мониторинга для учителя.

Главная архитектурная особенность системы — **Zero-Dependency развертывание (развертывание без зависимостей)**. Сервер поставляется в виде одного скомпилированного исполняемого файла (`.exe` для Windows и бинарного файла для ALT Linux). Это позволяет учителю информатики запустить полноценную LMS-систему в любом компьютерном классе двойным кликом мыши, без необходимости устанавливать Python, Docker, виртуальные окружения или базы данных.

## Архитектура и Выбранные Технологии

### 1. Бэкенд (Серверная часть)
*   **Фреймворк:** `Python` + `Flask`. Выбран за легковесность и простоту.
*   **База данных:** `SQLite` с включенным режимом **WAL** (Write-Ahead Logging). Обычный SQLite блокирует базу при записи, но режим WAL позволяет десяткам учеников одновременно отправлять результаты без ошибок блокировки. База данных представляет собой один файл `hamming_logs.db`, который создается в той же папке, откуда запущен сервер (рядом с `.exe`).
*   **Упаковка (Сборка):** `PyInstaller`. Инструмент "замораживает" интерпретатор Python, все зависимости (Flask, SQLAlchemy), HTML-шаблоны и статические файлы в один монолитный файл.

### 2. Фронтенд и Выполнение кода (Песочница)
*   **Интерфейс:** Стандартные HTML/CSS шаблоны + Vanilla JS.
*   **Среда выполнения кода:** **Pyodide (WebAssembly)**. 
    *   *Почему это круто:* Вместо того чтобы рисковать и запускать чужой (потенциально опасный) код учеников на сервере, мы отправляем интерпретатор Python прямо в браузер ученика. 
    *   Код компилируется и выполняется локально на машине ученика. Это гарантирует **абсолютную безопасность сервера** и **нулевую вычислительную нагрузку** на процессор сервера. Сервер только фиксирует финальный результат ("Задача решена верно").

## Пошаговый план разработки (Roadmap)

### Этап 1: Инициализация и Миграция базового кода
- [ ] Инициализировать Git-репозиторий в `D:\sch-edu-server`.
- [ ] Скопировать исходный код прототипа из `D:\py-env\hamming_web` (файлы `app.py`, `logic.py`, папки `templates` и `static`).
- [ ] Подготовить виртуальное окружение (`venv`) и файл `requirements.txt`.

### Этап 2: Адаптация под компиляцию (PyInstaller)
- [ ] Модифицировать `app.py`: добавить функцию динамического определения абсолютных путей до папок `templates` и `static` (использование переменной `sys._MEIPASS` при запуске из `.exe`).
- [ ] Настроить SQLAlchemy так, чтобы файл `hamming_logs.db` всегда сохранялся в текущей рабочей директории операционной системы (CWD), чтобы данные не пропадали после перезапуска скомпилированного сервера.
- [ ] Написать скрипт `build_windows.bat` для автоматической сборки проекта под Windows.

### Этап 3: Внедрение интерактивной WebAssembly песочницы (Pyodide)
- [ ] Подключить легковесный редактор кода на фронтенд (например, CodeMirror).
- [ ] Подключить библиотеку `pyodide.js` в шаблоны.
- [ ] Создать новую миссию/урок, где ученик должен написать функцию на Python (например, реализовать кодирование Хэмминга кодом).
- [ ] Написать JS-скрипт, который перехватывает написанный код, выполняет его через Pyodide со скрытыми `assert` тестами, и в случае успеха делает POST-запрос на сервер для записи результата в базу.

### Этап 4: Оптимизация Базы Данных и Учительской панели
- [ ] Добавить `engine_connect` слушатель в SQLAlchemy для принудительного включения режима `PRAGMA journal_mode=WAL;` в SQLite при старте приложения.
- [ ] Доработать страницу `/teacher`: добавить обновление в реальном времени, графики успеваемости класса и возможность скачать логи в формате CSV.

### Этап 5: Финальное Тестирование и Сборка
- [ ] Запуск `build_windows.bat`, проверка работоспособности получившегося `server.exe` на "чистой" Windows машине.
- [ ] Клонирование репозитория на машину с ALT Linux, написание скрипта `build_linux.sh` и сборка бинарника.
- [ ] Тестирование нагрузки (симуляция 30 одновременных входов учеников).
